# DSH 外部技能极速转换器

把别人写的技能包变成 DSH 能用的技能。命令行只有一个文件：`convert.py`，只用 Python 标准库，不需要装任何依赖。

**引擎位置**：本仓库的 `skill-converter/convert.py`（本机：`E:\dsh-skill\skill-converter\convert.py`，装到别处就改成本机路径）。下面所有命令里的 `convert.py` 都指这个绝对路径——引擎留在仓库里，`output/`、`_backup_`、报告也都生成在那里，不会污染技能目录。exe（`dist/DSH技能转换器.exe`，本机在 `E:\dsh-skill\dist\`）是同一个引擎的便携外壳，DSH 里有 Python，跑 `.py` 更快，不用双击 exe。

## 什么时候用它

- 用户给了一个 GitHub 仓库 / zip / 文件夹，里面是 `SKILL.md`，想装进 DSH。
- 用户说"这个技能包太长了""帮我压缩一下再装"。
- 用户想看看一个技能包里到底有什么，但不打算装。

不要用它去改已装好的技能正文，也不要用它执行包里的任何东西。

## 前置检查

1. 确认来源是什么：`https://github.com/<owner>/<repo>`、本地 `.zip`、本地目录。
2. 确认 Python 可用。本机优先用 DSH 自带解释器（不需要用户装 Python）：
   `C:\Users\Lenovo\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe`
3. 不要把 `~/.dsh/skills` 手动建目录 —— 一律用本工具落地，这样才有 `_backup_` 快照。
4. 如果用户自己动手、且不想碰命令行：让他双击 `dist/DSH技能转换器.exe`（本机 `E:\dsh-skill\dist\`；Release 里叫 `DSH-Skill-Converter.exe`，最新版直链，同一个程序，自带 Python，约 9 MB，问答式），你只需要在旁边告诉他选 1 还是 2。

## 标准流程（必须按顺序）

**第 1 步：预演，不写任何文件**

```bat
python convert.py "<来源>" --dry-run
```

多技能包（一个仓库里有多个 `SKILL.md`）会拒绝并列出候选。两种处理：

```bat
:: 只挑一个
python convert.py "<来源>" --name grilling --dry-run
:: 或者全部转（批量）
python convert.py "<来源>" --all --dry-run
```

用户说"全部装上/我全都要"时直接用 `--all`，别一个个跑。批量时有的技能会被跳过（比如带 `.sh`/`.py` 辅助脚本的），跳过清单要原样告诉用户、不要偷偷略过。一次也可以给多个来源：`python convert.py "<包1>" "<包2>" --all --dry-run`。

读输出里的四项：技能名 / 描述 / 正文行数 / 自动调用是否允许。行数太多（比如 > 400 行）就先跟用户说"这个正文很长，要不要我压一版"，然后按下面「压缩（省 Token）」走。

批量时报告是**可交互的**（纯本地单文件，不联网）：顶部搜索框 + 筛选（全部 / 仅手动 / 可自动调用 / 省 ≥5%），每个技能可折叠展开。跟用户交代时可以说"报告里能搜、能筛、能点开看明细"。

**第 2 步：把结果摊给用户看，问一句要不要装**

固定格式（不要改写字段、不要省掉"包含的工具及功能"这一项）：

```
转换预演：<技能名>
  包含的工具及功能：<description 一句话>；正文 <N> 行 / <大小>；<自动调用：允许 / 仅手动>
  原位置：<包内路径>
  会落地到：<目标目录>
  报告：<report-dry-run.html 路径>（可直接双击打开）
要不要我装进技能目录？装的话我会先说会动哪些文件，并且可以 --undo 一键回滚。
```

用户说装，才进第 3 步；用户只是想看，就停在这里。

**第 3 步：正式落地**

```bat
python convert.py "<来源>" --name <名字> --install
```

只输出到 `output/` 不装进技能目录，就去掉 `--install`。装完把这段话给用户：

```
已安装：<技能名>
  包含的工具及功能：<description>
  落在：<dest>
  备份：<backup 路径>（想撤销就执行下面这行）
  撤销：python convert.py --undo
```

**第 4 步：告诉用户怎么用**

装完的技能需要 DSH 刷新技能目录（一般一两秒）。如果 `disable-model-invocation: true`，要说清楚"AI 不会自动调，只能你手动 `/名字` 用"。

## 压缩（省 Token）

正文越长，每次对话越费 Token。两条路，**都不动原文**：

```bat
:: 路线 1：规则压缩（离线，先看能省多少）
python convert.py "<来源>" --name <名字> --compress --dry-run

:: 路线 2：你（AI）改写一版，交工具校验后再装
python convert.py "<来源>" --name <名字> --compact-file "改好的.md" --dry-run
python convert.py "<来源>" --name <名字> --compact-file "改好的.md" --install --use-compact
```

规则：

1. **先跑路线 1**。省 ≥ 5% 就够用；省不到 5% 说明这个包本来就紧凑，这时才提路线 2。
2. 路线 1 会连附件一起压：`refs/` 之类目录里的 `.md` 各生成一份 `<原名>.compact.md`，和原文件并排。只想要正文就加 `--no-attach`。图片、csv、pdf 永远不碰；单个附件 > 256 KB 跳过；省不到 3% 不生成。附件同样过红线校验，没过的不落盘。
3. 走路线 2 时，你自己改写那份 `SKILL.md`：**保留 frontmatter 原文**、保留所有 `--参数`、保留 `MUST/NEVER/必须/不要` 这类硬要求、保留编号步骤的数量和顺序、保留每段代码块。
4. 改写文件交给 `--compact-file`，工具会逐项校验；任何一项不过 → 退出码 3，**一个字都不要自己绕过**，把不过的项原样告诉用户。
5. 汇报要带上前后 Token 数（例如"正文 543 → 430，省 20.8%；附件 262 → 95，省 63.7%"），别只说"压缩好了"。
6. 压缩版和原文并排（`SKILL.compact.md`、`refs/xx.compact.md`）时，提醒用户"不喜欢就把这些文件删了，原文没动"；如果 `SKILL.md` 里写死了附件文件名，说明"AI 默认读的还是原版附件，要不要改引用由你定"。

## 撤销

```bat
python convert.py --list-backups   :: 看有哪些快照
python convert.py --undo           :: 回滚最近一次
```

`--undo` 按 `_backup_<时间戳>/manifest.json` 判断该删什么、该还原什么：新增的技能直接删掉，覆盖过的把旧目录还原回来。连按两次就退两步。

## 硬性约束（不要绕过）

- **绝不执行**包里的任何脚本；`.exe/.dll` 这类二进制一律不复制，选中技能里有就直接拒绝。
- `.sh/.bat/.ps1` 等脚本默认也不复制（该技能会被跳过或整次拒绝）。用户明确要装这类技能时，才加 `--allow-scripts`：脚本原样复制、工具绝不执行，并且必须在汇报里说清"包里带了脚本，已复制但没跑"。
- `.py/.js/.ts` 辅助代码会照常复制（官方技能如 pdf/docx 全靠它们干活），工具同样不运行；汇报时要带一句"随技能带了 N 个辅助代码文件，没运行"。
- 符号链接不落地、不跟随，只在报告的「提示」里列出来。
- 压缩包 > 5 MB、解压后 > 20 MB、文件数 > 500 直接拒绝 —— 这是防 zip 炸弹的，不要替用户放宽。
- 写入只发生在两处：DSH 技能目录（`--install`）或本目录下的 `output/`；动手前一定先写 `_backup_<时间戳>/`。
- 不改用户已装技能的正文；压缩只写 `SKILL.compact.md`，只有 `--use-compact` 才替换 `SKILL.md`，且替换前仍走 `_backup_`。
- 报告是单文件离线 HTML，不要往里塞外链、脚本、统计代码。

## 退出码

| 码 | 含义 | 你该做什么 |
|---|---|---|
| 0 | 成功（安装 / 输出 / 预演） | 按上面的话术汇报 |
| 2 | 用法错误（参数不对、来源不存在） | 看报错，修参数重跑 |
| 3 | 拒绝转换（多个技能、越界路径、有可执行文件、frontmatter 不合法） | 原样把拒绝理由转给用户，不要自己绕过 |
| 4 | 撤销失败（快照缺失、目标被改过） | 停下来问用户，别硬删 |

## 常见拒绝与应对

| 报错 | 原因 | 怎么办 |
|---|---|---|
| 这个包里包含多个技能，需要指定一个 | 仓库里有多个 `SKILL.md` | 让用户挑一个（`--name`），或 `--all` 全转 |
| 压缩包含越界路径 | 条目里有 `../` 或绝对路径 | 不要转，告诉用户包可能有问题 |
| 技能 X 里含可执行文件 | 选中技能目录里有 `.sh` 等 | 说明工具不复制脚本；批量模式下该技能会被跳过，要如实告知 |
| 压缩版文件只能配一个技能用 | 给了 `--compact-file` 又要转多个技能 | 加 `--name` 挑一个，或改用 `--compress` |
| name 与目录名不一致 | `name:` 和文件夹名不同 | 用 `--name` 指定目录名 |

## 给用户的汇报模板（智能复核）

装完或预演完，**必须**按这个形状说一遍，然后停下等用户回答：

1. 包含的工具及功能是哪些（一句话，别抄整段 description）
2. 会/已经动了哪些文件（新增 vs 覆盖，覆盖的备份在哪）
3. 怎么撤销（一行命令）
4. 问：要不要现在试一下 / 要不要我打开报告
